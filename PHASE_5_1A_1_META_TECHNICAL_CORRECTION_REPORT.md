Prior to creating the Meta Developer App or connecting Malik Tan's real Facebook account, a comprehensive technical correction and pre-connection security audit was executed.

This audit addressed six core technical realities:
1. **API Version Decoupling:** Decoupled Meta **Graph API** and **Marketing API** into distinct versioned constants in backend services. Both currently target **`v21.0`**, an active stable release supported by Meta through **January 21, 2027**.

5. **Campaign Metrics Precision:** Added ad account `timezone_name` (`Asia/Kuala_Lumpur`) and date boundaries (`date_start`, `date_stop`) to Marketing API insight queries, ensuring zero fabrication of campaign metrics.

## 2. Meta API Version Compatibility Matrix

### 2.1 Graph API vs. Marketing API Separation
Meta operates Graph API and Marketing API as distinct product architectures sharing the `https://graph.facebook.com/` host:
- **Graph API:** Manages identity, user profiles, Facebook Pages, webhooks, and raw Instant Form submissions (`/{leadgen_id}`). Supports automatic version fallbacks when non-breaking endpoints deprecate.
- **Marketing API:** Manages ad accounts, campaigns, ad sets, ads, budgets, and performance insights (`/insights`). **Unversioned calls are invalid**, and endpoints with breaking changes do **not** support auto-fallbacks.

### 3.2 Development Mode vs. Live Mode Technical Distinction
> [!IMPORTANT]
> **Critical Reality of Meta Development Mode:**
> - In **Development Mode**, the Meta platform permits calls to `leads_retrieval` **ONLY** for test leads generated by registered app users (Administrators, Developers, or Testers).
> - If an ordinary Facebook user (member of the public) interacts with an active Lead Ad while the app is in Development Mode, **Meta will NOT deliver webhook events to the server**, and any attempt to query `/{leadgen_id}` for that lead will return an HTTP 403 `(#200) Requires leads_retrieval permission to enjoy the full api` error.
> - **Production Multi-User / Public Buyer Requirements:**
>   1. Meta Business Verification (submission of official Malaysian business registration, e.g. SSM certificate).
>   2. Meta App Review submission for `leads_retrieval` and `pages_manage_ads` (including screencast demo).
>   3. Completion of Meta Data Protection Assessment (DPA).
>   4. Switching App status from Development to **Live**.

## 4. OAuth & Token Security Findings

| Security Requirement | Status | Implementation Details |
| :--- | :---: | :--- |
| **CSRF State Parameter** | **PASS** | Generated via `crypto.randomBytes(16)` with HMAC-SHA256 signature using `META_APP_SECRET`. 15-minute expiration window enforced. |
| **Timing Attack Protection** | **PASS** | State verification upgraded to `crypto.timingSafeEqual` in `verifyOAuthState`. Webhook signature verification also uses `crypto.timingSafeEqual`. |
| **Redirect URI Strictness** | **PASS** | Fixed backend URL (`https://asia-southeast1-property-71665.cloudfunctions.net/metaOAuthCallback`). Rejects unexpected host redirection. |
| **Long-Lived Token Handling** | **PASS** | Short-lived user token (1 hour) exchanged immediately via `grant_type=fb_exchange_token` for a 60-day long-lived User Access Token. |
| **Page vs. User Token Isolation** | **PASS** | User token is used solely for ad account/campaign queries. Page Access Tokens are retrieved separately via `/me/accounts` and stored per-Page for webhook subscriptions and `/{leadgen_id}` queries. |
| **Server-Only Token Storage** | **PASS** | Stored exclusively in Cloud Firestore collection `_private_meta_credentials/{ownerId}`. Excluded from client-facing Firestore security rules. |
| **Token & Secret Leakage Prevention**| **PASS** | Zero tokens or secrets returned in callable Cloud Functions. `maskSecret` utility applied across all scripts and logs. No passwords requested or stored. |

## 5. Webhook Readiness Findings

1. **GET Handshake Verification:**
   - Validates `hub.mode === 'subscribe'` and `hub.verify_token === META_WEBHOOK_VERIFY_TOKEN`.
   - Returns raw `hub.challenge` with HTTP 200.
   - PII/Secret safety: Updated log statement to output `{ receivedLength: ... }` rather than leaking the raw received token string.

2. **POST Event Verification & Deduplication:**
   - Validates `x-hub-signature-256` header using HMAC-SHA256 across `req.rawBody` with `crypto.timingSafeEqual`.
   - Idempotency enforced via `collections.metaIngestedLeads.doc(leadgenId)`. Repeated deliveries return `{ success: true, isDuplicate: true }` without re-triggering ingestion.

3. **Lead Retrieval Resilience:**
   - If Graph API lead fetch fails (e.g. expired Page token or transient rate limit), the error is logged with PII-safe metadata (`leadgenId`, error message).
   - Ingestion pipeline falls back gracefully to synthetic/webhook data without crashing Cloud Functions worker.

## 6. Campaign Insights Readiness

1. **Currency & Time Zone:**
   - `fetchUserAdAccounts` queries `currency` (MYR) and `timezone_name` (`Asia/Kuala_Lumpur`).
   - Ensures daily budget thresholds and ad spend calculations match Malaysian Ringgit.

2. **Core Insights Metrics:**
   - Querying: `spend`, `impressions`, `reach`, `clicks`, `ctr`, `cpc`, `cpm`, `actions`, `date_start`, `date_stop`.
   - Action parsing extracts both standard `lead` and `onsite_conversion.lead_grouped`.

3. **Metric Integrity & Non-Fabrication:**
   - Downstream `calculateBuyerQualityMetrics` computes `costPerQualifiedBuyer` and `costPerViewingAppointment` **strictly from actual Firestore prospects**.
   - If qualified prospects or viewing appointments are zero, the metric evaluates to `null` (never fabricated or assumed).
   - All synthetic pilot campaigns are explicitly stamped with `dataSource: "MOCK_SIMULATED"`.
